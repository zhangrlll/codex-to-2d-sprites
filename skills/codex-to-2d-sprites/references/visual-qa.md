# 动画视觉验收：单帧、连续播放、动作切换

用于本流程的新素材验收、继续制作和定点返修。三种检查方式都要覆盖；文件齐全、alpha 合格或接触表好看不能代替视觉验收。检查用户要求的全部动作和方向：8 方向任务覆盖八方向，4 方向任务只覆盖四方向；不凭此清单新增用户未要求的动作。

## 1. 建立对照基准

从用户风格图、已通过的角色母版和对应 3D 底稿建立本角色的外观基准。记录发色、肤色、衣服颜色、发型、脸型、头身比例，以及实际存在的眼镜、袖条、鞋袜、饰品等特征；不要求每个角色都有这些细节。

各动作共用这套基准。可以按方向和遮挡增加参考，但不能为每个动作各自接受不同发色或身体比例。母版需要先与用户参考和 3D 身份特征核对，不能把第一张有问题的生成图自动视为正确答案。

保留动作、方向、帧索引、采样时刻、画布、公共锚点和对应 3D 源帧的映射。检查已有素材时优先查生产记录；缺失底稿或母版需标明，能够重建则重建，否则不能声称完成了源姿势或身份对照。

## 2. 九项检查表

| 检查项目 | 重点 |
| --- | --- |
| 角色外观一致性 | 跨动作与帧间的发色、肤色、服装底色一致；发型、袖条、鞋袜、附件没有突然改变或消失。 |
| 头身比例 | 头部大小、脸型、四肢粗细及头颈连接稳定；与对应源姿势比较，区分合理透视、遮挡、设计形变和生成漂移。 |
| 朝向与透视 | 同方向下头身朝向合理，转向时不突然换脸或改变发型结构；翻滚露出面部与否以源姿势为准。 |
| 动作与肢体结构 | 手脚无错位、缺失和非预期穿插；肘膝弯曲合理，翻滚各阶段连贯。 |
| 位置与地面接触 | 站立脚底不漂移，走跑不明显滑步，翻滚不穿地，跳跃有清楚腾空与落地；世界位移和已画入帧的位移不重复叠加。 |
| 逐帧稳定性 | 头发、轮廓、五官、衣服细节不闪烁、抖动或突然膨胀收缩；有意的头发摆动等应符合连续动作。 |
| 节奏与循环接缝 | 无不合理卡顿，预备、发力、缓冲符合动作目的；末帧接首帧没有姿势、颜色或位置跳变。 |
| 动作切换 | idle ↔ walk ↔ run 和跳跃/翻滚前后，外观、比例、脚底锚点和整体位置不突变；移动中不拖着站立前后置姿势滑行。 |
| 透明边缘与游戏内表现 | 黑、白和实际场景背景下无绿边、杂点、灰边或残影；正常游戏显示尺寸下轮廓清晰、方向和动作易辨。 |

## 3. 固定检查顺序

### 对照与单帧检查

1. 每个方向制作跨动作对照板：idle、walk、run 选择相近头部朝向、可比姿势的代表帧并排；再加入 jump/roll 的起始、腾空/倒置和恢复姿势。先排查发色和头身比例，再逐项检查其余外观特征。
2. 对照板共用画布显示比例、地面线和锚点；每张标记动作/方向/帧索引。可另附头脸放大裁片，但不能把裁片各自归一到相同头部大小，掩盖漂移。
3. 将可疑 2D 帧与其对应 3D 源帧并排或叠加检查。3D 底稿用于判断几何、姿势、朝向和透视；2D 母版用于判断目标画法与颜色，不强迫两者像素一致。
4. 逐一查看全部最终帧，在正常显示尺寸判断观感，在原始分辨率/放大视图检查疑点。可分批制作可读接触表；只看缩小后的总图不算逐帧完成。

颜色比较聚焦相同语义区域，例如头发主体色，排除背景、皮肤、描边、透明边缘和局部高光；灯光阴影差异也要结合参考判断。头部测量结合轮廓、五官/颈部参考点及对应 3D 投影变化。数值统计用于定位异常，容差按本角色与源姿势确定；不得用固定颜色阈值或固定头框尺寸自动宣布通过。

### 连续播放检查

全部动作 × 方向均按实际帧时长、预期游戏尺寸以正常速度完整播放；idle/walk/run 等循环动作至少连续三轮。检查整段节奏和末帧→首帧，不能只看其中一个方向。

随后慢速播放并逐帧定位颜色闪烁、比例波动、脚滑和卡顿，至少包含动作极值、接触帧及已发现的异常邻域。播放速度由预览工具控制，不为掩盖问题而修改交付时序。非循环动作完整检查准备、运动、落地/起身和恢复。

### 动作切换与交互检查

在全部请求方向测试以下适用组合，保留实际覆盖记录：

- idle → walk → idle、idle → run → idle、walk ↔ run。
- idle/walk/run → jump 或 roll → idle；从 walk/run 发起时，另测保持移动并恢复原步态。
- 移动中变向，包括斜向与相邻/相反方向；反复启停、切换走跑，在步态不同阶段触发跳跃/翻滚，并测试动作中释放方向键与落地后的表现。

只测场景实际支持的切换；未要求/不存在的动作标为“不适用”，不伪造覆盖。记录每个方向的进入状态、动作、返回状态和触发阶段，不以一段向右演示代表八方向。

Godot 可用时，复用用户场景或建立只用于验收的最小场景，加载本次最终 PNG/图集及真实时序、锚点、状态切换和移动参数。可手动输入或脚本发送输入驱动实际控制器，保留运行画面/日志；只调用节点的方法或检查动画名不证明画面和运动正确。用户只需要素材时无需额外交付完整游戏。

Godot 不可用时，继续用可切换动作的预览检查视觉边界，把引擎交互标为“未验证”，不称为通过 Godot 验收；若任务明确要求 Godot 场景则该部分仍未完成。无真实场景背景时使用接近用途的临时背景并注明。仅需素材的任务可在其适用检查通过后交付，说明引擎与实际背景尚未验证；以后接入真实场景时再补验，不无限阻塞素材交付。

## 4. 修复与复检

按原因修复受影响的帧、区段或源动作，保持已通过的身份与姿势：

- **发色/肤色/服装漂移**：回到统一母版，结合当前源帧，用 ImageGen 修正目标区域及邻近过渡；若按工具规则和已有授权采用局部调色，保护高光、描边、alpha 和其他材质，禁止整张全局染色当作通用修复。
- **头部膨胀或脸型改变**：先排除源姿势透视和相机/导出尺度问题。生成变形返回对应帧修图；仅在整帧尺度误差已验证时做等比校准。不能逐帧强制头框等大、拉伸身体、冻结所有动作的头或复制 idle 头去覆盖转头/倒置姿势。
- **脚滑/切换跳位/前后置滑行**：核对源动作、帧时长、公共锚点和根位移，再按本次接触姿势处理原地与移动触发片段。不能套用其他角色的裁剪索引，也不能靠长时间交叉淡化掩盖错误外观或位置。
- **运行时修正**：Shader 修正头部、呼吸等时，分别验收原始交付 PNG/图集和引擎最终画面。引擎效果不能宣称已经烘焙进 PNG；素材任务中的明显源帧错误仍需修复，或明确列为未通过。

每次修复后重看受影响帧、前后邻帧、整段循环和相连的动作切换，并检查同方向其他动作。更换母版、全局颜色、相机、公共尺度或锚点时，重查全部受影响动作/方向。重新导出后核对交付文件确实是复检通过的版本。

## 5. 验收记录与通过条件

沿用项目的检查记录格式，至少保存：

- 外观基准及每个方向的跨动作对照板；可疑源帧/成品帧和修复前后对照。
- 动作 × 方向的逐帧与连续播放覆盖；适用切换的方向、进入/返回状态、触发阶段与结果。
- 每个问题的动作、方向、帧索引/播放时间、现象、原因、处理方式、复检结论和证据路径。
- 黑/白/场景背景及正常显示尺寸检查，最终文件版本或哈希；分别标明“通过 / 未通过 / 未验证 / 不适用”，附原因。

只有应做检查均完成且没有明显发色跳变、比例漂移、肢体错误、闪烁、穿地或切换突变，才可标记视觉验收通过。轻微且不影响正常尺寸观感的差异如实记录；缺证据的检查不得记为通过。返修遵循主 Skill 的重试/停止规则，不无限重绘，也不以“AI 难免波动”把已知明显问题直接降为已完成。
