# ImageGen、透明帧与交付

## 关键帧、风格母版与相邻帧编辑

从本次模型提取可验证的身份特征：发型、脸、眼镜/附件、服装、颜色和身体比例。用户提供风格参考时采用该参考；否则先从代表性 3D 渲染制作母版并自行检查身份一致性。正常小样通过后直接继续，无需另设用户批准关卡。

先从每个方向的采样序列中选择能约束动作变化的关键姿势：例如步态的接触/经过姿势、跳跃的起跳/最高点/落地、翻滚的扑身/倒置/支撑恢复。关键姿势数量按动作复杂度决定；这里的关键帧是最终画面中的代表姿势，不等同于骨骼文件里全部关键帧。

用对应 3D 底稿精修这些关键帧，核对身份、比例、朝向和动作，再用通过的关键帧指导附近其余帧。每个邻近帧仍以自己的 3D 底稿为姿势依据，不能复制关键帧姿势或仅靠图像混合代替动作。保持全局母版参与，避免只参考上一张生成图导致误差逐步累积；跨两个关键姿势的区段需同时核对两端外观。

按相邻区段扩展并检查小组连接处，直到全部目标帧都完成风格化。遇到新遮挡、转头或倒置，不强行沿用不适用的正面关键帧，增加该姿势的参考。这个流程控制绘制顺序和参照关系，不承诺 ImageGen 自动插值或绝对一致。

使用当前可用的内置 ImageGen 及其工具规则。先查看每个本地编辑目标，再调用图片编辑。明确区分：图 1 是对应姿势底稿；图 2 是身份/风格母版；可选图 3 是已通过的同方向风格参考，不能借用其动作姿势。不要把文字提示当作姿势锁定的替代品。

优先单帧或少量相邻帧。单动作、单方向的 4×3 十二帧工作板曾可用，但仅在每帧有足够有效分辨率、人物分离且布局可靠时采用；复杂遮挡、细节丢失或倒置失败时缩小批次。每组都保留生成原文件、实际提示词和源帧映射。

提示词骨架（填入实际观察，不靠文字虚构动作）：

> 图 1 是本次编辑目标，按从左到右、从上到下的顺序逐一保留全部姿势。图 2 只提供身份与 2D 风格。将角色绘制为〔指定风格〕，保留〔特征清单〕。严格保持每帧头部旋转、四肢、遮挡、眼镜位置、朝向和相对尺度，尤其保持倒置/腾空姿势。输出〔真实透明，或已决定的均匀底色〕，不要棋盘格、地面阴影、文字、网格线或特效。人物间留出间隔，不裁切、不增减帧，不把下蹲或翻滚姿势放大成站立高度。

背面方向并不意味着每一帧都看不见脸：翻滚倒置后可能露出面部，以 3D 底稿为准。发现坏帧时只修改对应帧/小组；没有用户要求，不改动角色服装、附件或动作种类。

## 真透明与绿幕备选

检查 PNG 模式和 alpha 实际分布；RGB 图片中的棋盘或完全不透明的 RGBA 都不能当透明成品。先按工具能力请求真正透明；失败时可采用用户偏好的均匀 #00FF00 绿幕，再用脚本去底、对齐、切帧和拼接。当前工具若要求用户明确允许脚本处理，则检查会话已有授权；已授权直接继续，不重复提问。本 Skill 不代替缺失的授权。

要求背景纯色、无渐变、纹理、地面阴影和反射染色。先检查人物是否含该底色；绿色服装、徽章、绿色眼睛不能被全局阈值删掉。优先改用与角色不同的底色，或使用受控背景蒙版保护主体。边缘连通只能作为背景判断的一部分：内孔、透明镜片、与背景相接的同色服装都要单独检查。

纯绿且人物没有绿色时，可把以下思路用于抗锯齿边缘的去底实现：

- 估计绿色 excess = max(0, G − max(R, B))，近似覆盖率 alpha = clamp(1 − excess/255)。
- 在可信背景/边缘区域，减去绿色底色贡献，再恢复前景颜色；alpha 为零的 RGB 清零。
- 这只是针对受控色板的近似方法，不是通用分割器。用黑、白和棋盘三种背景检查绿边、灰边、半透明残影以及白袜/镜片是否误删；失败时调整蒙版或重新生成合适底色。

## 拆分与对齐

不要假定生成图片具有请求的像素大小、网格边界或准确帧数。先核实实际尺寸及人物数量。名义网格越界时，识别实际人物轮廓及其行列顺序再切分，避免切掉鞋、手或头发。

连通区域可帮助定位，但“取最大的 N 个区域”不适用于所有角色：分离的武器、飘带、断开的脚/手绘制和接触的相邻人物都需人工语义核对。每个输出帧必须与对应源姿势一一匹配；不能可靠分离时重绘单帧或更小的组。

采用公共画布与锚点，先尝试同组等比缩放；存在绘制尺寸漂移时，可对每帧按对应源姿势的尺度与位置做等比校准。不要把站立、下蹲、腾空、翻滚一律归一到同样的人物高度，不做非等比拉伸。源轮廓中心/下边界可提供初始定位，但手臂伸展会改变外框中心，应结合身体/脚底参考点检查左右抖动。

如果尺寸偏差来自错姿势或身体比例变形，返回 ImageGen 修图；不能靠对齐脚本掩盖。保留源/成品外框、应用缩放、位移和异常帧记录。

## 验收及最小交付

视觉检查覆盖每帧和各方向完整播放：姿势顺序、肢体数量、朝向、头发/衣物/附件身份、脚底接触、穿地、循环接缝及尺寸抖动。接触表用于逐帧检查，GIF/网页用于时序检查；不能用一次静态截图证明流畅，也不能把像素检查通过等同于视觉完美。

脚本验证至少包括：

- 用户所需动作 × 方向 × 帧数全部存在，文件可解码，画布尺寸与实际 alpha 正确。
- 全部帧无裁切、无空帧，检查不合理重复帧；色键残留检测阈值需结合角色色板，不能把绿色角色像素视为错误。
- 图集每一格与对应独立帧一致；缩小版与其确定性缩放结果一致。检查 PNG alpha，GIF 灰底仅作为预览。
- 顺序、锚点、每帧时间、循环属性和完整时长一致。重新打开源文件确认动画/纹理，压缩包检查完整性。

输出结构由项目决定，通常包括：

| 交付内容 | 约定 |
| --- | --- |
| 独立 PNG | frames/动作/方向/000.png…；公共画布，真实 alpha。 |
| 动作图集 | 列为帧，行为方向；行序按主 Skill，不能遗漏方向。 |
| 多动作总图集 | 在纹理尺寸适合用途时提供；明确动作行块顺序，避免生成超大难用图集。 |
| 时序清单 | 动作、方向、源帧、持续时间、是否循环、画布/锚点、图集坐标和根位移单位。 |
| 可看预览 | 每动作 GIF 或可切换动作/方向、暂停、逐帧、调速的本地 HTML。 |
| 可编辑来源 | 带全部指定动作及纹理的模型源文件；保留底稿与生成记录供后续修改。 |
| 简短说明与 ZIP | 图集切分、循环/单次播放、位移是否已画入帧，实际提示词与验证报告。 |

最终答复给出素材包与预览的可点击路径，说明实际数量和检查结果。区分输出画布像素与生成插画的原生像素；轻微发丝/衣褶差异应如实说明，不承诺绝对帧间一致。
